# 晨報系統 · Morning Brief

一個給台灣使用者的每日晨間簡報頁面。起床點開，一眼看完今天的天氣、行程、待回信件、自選股與一節經文。整頁配色會隨當天天氣與氣溫變化。

不是 App，是一個單頁 HTML，發佈成一個固定網址，可以「加到主畫面」當 App 用。頁面本身不存資料——天氣、股價、信件放在 artifact 的小型資料庫裡，頁面開啟時去讀；經文與時鐘則完全在瀏覽器端算。

## 長什麼樣

由上而下六塊：

| 區塊 | 內容 |
|---|---|
| 時間列 | 即時走的時鐘、日期、資料更新時間戳 |
| 節慶橫條 | 只在當天是節慶或教會節期時出現，20 款手繪風格 SVG 圖樣 |
| 天氣 | 地點、最高／最低溫、天況、降雨機率、預報時段、一句白話提醒 |
| 需要你注意 | 今天的行程（頁面自己即時讀 Google 日曆）、等你回信的信件 |
| 自選股 | 台股在上、美股在下，紅漲綠跌（台股慣例） |
| 今日經文 | 四福音隨機一節加白話解釋，頁面自己每天換 |

### 配色隨天氣變

整頁的底色、卡片、字色、圖示、分隔線都吃 `:root` 的 CSS 變數，由 `<html>` 的 `data-sky` 屬性決定，`skyOf()` 依天況、降雨機率、最高溫自動判斷：

| 主題 | 觸發條件 | 視覺 |
|---|---|---|
| `warm` | 晴，26–32°C | 暖黃，太陽光芒緩慢旋轉 |
| `hot` | ≥33°C | 紅橘，熱氣暈呼吸 |
| `cloudy` | 陰天 | 灰 |
| `rain` | 降雨機率 ≥30% | 灰藍，斜雨絲飄落 |
| `storm` | ≥70% 或雷雨 | 深藍夜色，密雨絲 |
| `cool` | ≤20°C | 淺青，雲緩慢飄移 |

動畫在 `prefers-reduced-motion` 下全部關閉。

### 資料與畫面分離

早期版本是「排程讀回整份 HTML → 改掉中間幾個數字 → 把整份吐出來重新發佈」。那份 HTML 有 51 節經文、38 區座標表、20 款 SVG 圖樣、六組色板，光是原封不動抄一遍就是兩萬多個 token 的輸出——改三個數字，代價是重打一整本書。而且只要輸出中途斷掉，整輪就白做，**不會有任何錯誤訊息**，頁面只是安靜地停在上一版。

現在改成：

```
排程 ──→ 寫入 artifact 資料庫的 brief/latest（約 2 KB 的 JSON）
                          │
頁面開啟 ──→ claude.use('db') 讀這份文件 ──→ 更新畫面
                          │
              讀不到就用 HTML 裡烘焙好的那份快照
```

文件長這樣：

```json
{
  "updated": "9/14 13:40 · 台股收盤",
  "span": "白天 06 時–18 時",
  "counties": { "高雄市": { "wx": "晴時多雲", "pop": 20, "lo": 26, "hi": 32 }, "...": {} },
  "fest": null,
  "stocks": [{ "name": "台積電 2330", "price": "2,380.00", "chg": "−30.00",
               "pct": "−1.24%", "when": "9/14 收盤", "dir": "dn" }],
  "stockNote": "……",
  "mail": [], "agenda": [], "verse": null
}
```

縣市座標表、SVG 圖樣、色板、經文陣列這些**不會變的東西留在 HTML 裡**，只有會變的數值進資料庫。寫入從 60 KB 降到 2 KB。

這也讓靜態部署變得乾淨：`claude.use` 不存在時（例如放在 Vercel 上）那段 script 直接跳過，頁面顯示 HTML 裡烘焙好的快照，不會壞掉也不會空白。

### 經文：每天抽一節，但同一天固定

頁面內建 51 節四福音經文（和合本，公有領域），每節附兩三句白話解釋。選哪一節**不靠 AI 隨機**——那樣會重複，實測連續好幾天抽到同一節。改成用日期當種子的洗牌抽籤：

```js
day    = Math.floor(Date.UTC(y, m, d) / 86400000)   // 1970 起算的天數
cycle  = Math.floor(day / 51)                       // 第幾輪
order  = fisherYates(0..50, seed = hash(cycle))     // 這一輪的抽籤順序
verse  = VERSES[order[day - cycle * 51]]
```

所以：同一天不管刷新幾次都一樣（有「今天的經文」的感覺），跨過午夜才換，連續兩天會跳到完全不同的書卷，一輪 51 天之內不重複，下一輪換種子重洗、順序也不同。**這段完全在瀏覽器算，排程掛掉照樣每天換。**

教會節期（受難日、復活節、五旬節、感恩節、聖誕節）由排程寫進資料庫的 `verse` 欄位覆蓋當天的抽籤；平常日那個欄位是 `null`。

## 架構

```
四個 Claude 排程任務（07:00 / 每小時 08-22 / 09:05 / 13:35）
    ├── 中央氣象署 F-C0032-001 ─┐
    ├── Google Finance（盤中）──┤
    ├── 證交所每日成交資訊 ─────┤──→ 寫入 artifact 資料庫 brief/latest
    ├── stockanalysis.com（美股）┤                      │
    ├── Google Calendar ───────┤                      │
    └── Gmail ─────────────────┘                      │
                                                       ↓
                               手機主畫面圖示（加到主畫面）
                                                       │
        頁面自己再做兩件事 ←───────────────────────────┘
          ├── 向 Google 日曆即時重抓行程（每次開啟＋每 5 分鐘）
          └── 依日期抽今天的經文（純前端，不靠排程）
```

四個排程分工：

| 排程 | Cron（UTC） | 台灣時間 | 做什麼 |
|---|---|---|---|
| 每日晨報 | `0 23 * * *` | 07:00 | 天氣、節慶橫條、行程、信件、股價（前一交易日收盤＋美股昨夜收盤）。唯一會推播的 |
| 每小時更新 | `0 0-14 * * *` | 08:00–22:00 每小時 | 天氣、待回信件、行程備援、時間戳每輪都換；台股盤中價只在 10、11、12、13 點，官方收盤覆蓋只在 16 點 |
| 開盤後五分鐘 | `5 1 * * *` | 09:05 | 只動台股三列（盤中價） |
| 收盤後五分鐘 | `35 5 * * *` | 13:35 | 只動台股三列（收盤價） |

股價一天更新八次：07:00、09:05、10:00、11:00、12:00、13:00、13:35、16:00。美股只在 07:00 換一次——台股交易時段美股本來就休市。

### 每一項的更新時機

| 項目 | 什麼時候換 |
|---|---|
| 時鐘 | 每秒（頁面自己跑） |
| 資料庫 brief/latest | 排程寫入後，所有開著的頁面即時更新 |
| 今日經文 | 每天午夜（頁面自己算，不靠排程） |
| 今日行程 | 每次打開頁面即時重抓，頁面開著時每 5 分鐘再抓一次 |
| 天氣、配色 | 07:00，之後 08:00–22:00 每小時 |
| 待回信件 | 07:00，之後 08:00–22:00 每小時 |
| 節慶橫條 | 07:00 |
| 台股 | 07:00、09:05、10:00、11:00、12:00、13:00、13:35、16:00 |
| 美股 | 07:00 |

23:00–06:00 沒有任何排程，那段時間除了時鐘與過午夜換的經文之外都是前一晚 22:00 的快照。

行程是唯一「頁面自己會重抓」的外部資料——透過 Claude Artifact 的連接器能力直接呼叫 Google Calendar，所以在日曆新增或刪除行程後，重新整理頁面就會反映。天氣與股價做不到，原因見下面。

## 部署到 Vercel（靜態展示版）

`index.html` 是一份完整、可獨立開啟的單頁，沒有任何後端、沒有建置步驟，把 repo 接上 Vercel 就會自動部署。

**這份靜態版做得到：** 完整版面與互動、配色隨天氣主題切換、59 個地點選單（選擇存在 `localStorage`）、經文每天自動換、即時走的時鐘。

**做不到，以及原因：**

| 功能 | 靜態版狀態 | 原因 |
|---|---|---|
| 天氣、股價自動更新 | 顯示部署當下的快照 | 資料放在 artifact 的資料庫裡，靜態主機上 `claude.use('db')` 不存在，讀不到；瀏覽器直接打氣象署與證交所 API 又會被 CORS 擋 |
| 行程即時讀 Google 日曆 | 不會執行 | 走 Claude Artifact 的連接器管道（`claude.use('mcp')`），離開該環境時 `claude` 未定義，那段 script 會直接 return，留下靜態內容 |
| 待回信件 | 顯示快照 | 同上，Gmail 走連接器 |

要讓靜態版也會自己更新天氣，可行方向是加一個 serverless function（Vercel Functions）當代理去打氣象署 API——金鑰放 Vercel 的環境變數，**不要寫進前端**。本 repo 沒有做這件事。

## 自己架一份

1. **申請中央氣象署授權碼**（免費）
   到 [氣象資料開放平臺](https://opendata.cwa.gov.tw) 註冊會員（註冊頁在另一個網域 `pweb.cwa.gov.tw/emember/register/authorization`，opendata 那頁只有登入框，「加入會員」是登入框下面一行小字），登入後在會員資訊取得 `CWA-` 開頭的授權碼。
2. **連接 Google 日曆與 Gmail**
   在 claude.ai 的設定 → 連接器連上，並在對話裡啟用。
3. **建立四個排程任務**
   把 `prompts/` 裡的四份指令貼進 Claude 的排程任務，cron 用 UTC：
   - 每日晨報：`0 23 * * *`（台灣時間 07:00）
   - 每小時更新：`0 0-14 * * *`（台灣時間 08:00–22:00）
   - 開盤後五分鐘：`5 1 * * *`（台灣時間 09:05）
   - 收盤後五分鐘：`35 5 * * *`（台灣時間 13:35）

   記得把指令裡的 `<YOUR_CWA_KEY>`、`<YOUR_EMAIL>`、`<YOUR_ARTIFACT_URL>` 換成你自己的。
   **注意排程存的模型**：實測曾經因為排程被存成一個當下跑不起來的模型，四個排程連續幾天每次一啟動就在 10 秒內失敗，頁面整整五天沒更新、也沒有任何錯誤訊息浮到表面。排程建好後去看一次 `last_run` 的狀態，別假設它有在跑。
4. **加到手機主畫面**
   Chrome 開頁面 → ⋮ → 安裝並建立捷徑。

## 資料來源與踩過的坑

這一節是這個 repo 最有價值的部分——每一條都是實測出來的。

### 天氣：中央氣象署開放資料

用 `F-C0032-001`（36 小時縣市預報），**一次呼叫回傳全台 22 縣市**，是這個系統的天氣骨幹。

- `F-D0047` 系列（鄉鎮預報）若把**多個中文要素或多個地點用逗號串起來，一定回 401**。一次只能問一個地點、一個要素。全台 368 區要上千次呼叫，不現實。
- 實測氣象署的**區級預報在同一片市區內幾乎沒有差異**（高雄市區八個區的最高溫完全相同），真正有差的是山區與市區之間。所以本系統顯示精確區名、數字用縣市級，並在頁面上誠實標註。
- 曾經用過的 `weather-atlas.com` **與氣象署差距極大**（一邊說雷雨機率近 100%，一邊是晴時多雲 20%），已棄用。

### 台股盤中：Google Finance

`https://www.google.com/finance/quote/2330:TPE?hl=zh-TW`（`0050:TPE`、`2454:TPE` 同理）

這是繞了一圈才找到的答案。先試過的三個來源全部不行：官方盤中 API `mis.twse.com.tw` 被 robots.txt 擋；`stockanalysis.com` 的台股延遲好幾小時（晚上八點還顯示上午 10:07 的價，數字甚至方向都錯）；Yahoo 股市抓下來是好幾天前的快照。**Google Finance 是真即時**，回傳還附「9月14日, 上午10:44:05 [GMT+8]」這種時間戳可以驗。

兩個一定要做的防呆：

1. **頁面下方有「相關股票」區塊，很容易抓錯檔。** 實測抓 2454 時第一次拿回 1,485 元、時間戳 1 月——那是別檔的數字。WebFetch 的 prompt 必須明寫「只取頁面最上方的主報價，不要下面的相關股票」。
2. **抓回來要驗。** 時間戳必須是今天且在交易時段內；價格與 previous close 的差距要在漲跌幅上限 10% 以內；previous close 要跟頁面上原本那檔的價格對得起來。任一項不過就保留原值不動——寧可顯示舊價，也不要顯示錯價。

### 台股收盤：證交所官方每日成交資訊

`https://www.twse.com.tw/exchangeReport/STOCK_DAY?response=json&date=YYYYMMDD&stockNo=2330`

資料陣列欄位順序：日期, 成交股數, 成交金額, 開盤價, 最高價, 最低價, **收盤價**, 漲跌價差, 成交筆數。日期是民國格式。漲跌幅要自己算：`漲跌價差 ÷ (收盤價 − 漲跌價差)`。

- **收盤後才有當天資料**，而且 13:35 通常還沒出來；`0050` 這類 ETF 常比個股再晚一到兩小時。所以 13:35 那輪先用 Google Finance 的最終價並標「待官方確認」，16:00 再用官方數字覆蓋。
- 官方數字是最終版，會跟盤中價有些微差異（盤後定價、零股等），以官方為準。

### 美股：stockanalysis.com

`https://stockanalysis.com/stocks/<ticker>/` — 美股資料準確，含盤前價與收盤時間戳。

### 行程與信件：Google 連接器

日曆與 Gmail 都走 Claude 的連接器。信件只列「對方問了你、你還沒回」的，群組信、電子報、系統通知、廣告排除，疑似命中的要讀完整討論串確認。

### 教會節期：自己算

不在任何公開日曆裡。用 Anonymous Gregorian 演算法算復活節，其餘由它推導：

```python
def easter(y):
    a=y%19; b=y//100; c=y%100; d=b//4; e=b%4; f=(b+8)//25; g=(b-f+1)//3
    h=(19*a+b-d-g+15)%30; i=c//4; k=c%4; l=(32+2*e+2*i-h-k)%7
    m=(a+11*h+22*l)//451
    return date(y, (h+l-7*m+114)//31, ((h+l-7*m+114)%31)+1)
```

受難日 = 復活節 − 2 天；五旬節 = 復活節 + 49 天；感恩節 = 11 月第四個週四。（驗算：2026 年復活節 4/5、受難日 4/3、五旬節 5/24、感恩節 11/26。）

農曆節日（春節、端午、中秋、元宵、七夕、中元、重陽）不用自己算——Google 的「台灣的節慶假日」日曆每年提供正確日期。

## 已知做不到的事

寫在這裡，省下重複踩坑的時間。

- **頁面不能連任何外部服務。** Artifact 的 CSP 封鎖所有對外請求，所以天氣與股價無法在頁面端即時抓，只能由外部寫進資料庫。日曆是唯一例外，因為它走連接器管道。
- **WebFetch 對同一個網址有 15 分鐘快取。** 同一輪裡重複抓氣象署會拿到上一次的舊時段（明明是上午卻回凌晨 00–06 時的預報）。在網址尾巴加個變動參數就能繞過。
- **`navigator.geolocation` 永遠拿不到。** 瀏覽器回 `Geolocation has been disabled in this document by permissions policy`——這是平台的 iframe 政策，改不了。本系統改用 59 個地點的選單（高雄 38 區 ＋ 其他 21 縣市），選擇存在 `localStorage`。
- **排程最短間隔 1 小時。** 5 或 10 分鐘一次會被拒絕。
- **排程任務寫不進 artifact（未解）。** 實測排程確實會啟動、跑十幾分鐘、狀態回報 `SUCCEEDED`，但把已發佈的 HTML 抓下來逐字比對，以及查資料庫文件的 version，都證明**它從來沒有真的寫入過任何東西**。無論是舊的「重新發佈整份 HTML」還是新的「只寫 2 KB 資料庫」都一樣，所以不是輸出長度的問題。目前最可能的解釋是發佈 artifact 與寫入它的資料庫都需要使用者授權，而排程是無人看顧的工作階段，沒有人能按同意，於是它「順利地」結束、什麼也沒做。
  這一條是本專案最大的未解問題，也是最值得記下來的教訓：**「排程狀態顯示成功」不等於「它真的做了事」**。驗收要看資料本身有沒有變，不要看狀態碼。
- **常駐桌面 widget 做不到。** 安卓 widget 只能由原生 App 提供，而這個頁面需要登入 claude.ai，widget App 抓不到。可行方向是把純資料寫到公開主機（例如 GitHub Pages 或雲端硬碟公開檔）再配 KWGT，但公開的那份只該放天氣、股價、經文，不要放行程與信件。
- **iPhone 內建行事曆的行程進不來。** 它預設存 iCloud，而連接器目錄裡沒有 iCloud 或 CalDAV 的連接器。解法是在 iPhone 設定 → 行事曆加入 Google 帳號並設為預設行事曆。
